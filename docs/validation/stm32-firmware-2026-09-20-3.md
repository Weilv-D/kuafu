# STM32 Firmware Logic Review — 2026-09-20 (third record)

This record documents an independent fifth-pass review of the firmware.
Per the task framing, the review started from the source alone: the
architecture and every module were re-derived before any prior record or
changelog entry was read. The four earlier records (07-16, 09-13, 09-16,
and the two 09-20 passes) were consulted only afterwards, to check that
their invariants and fixes still hold — every one of them was re-verified
clean by this pass's own derivation.

It is a software record: no hardware was flashed or driven.

## Scope and method

1. **Architecture pass** — module partition (scheduler / control section /
   safety machine / actuator supervisor / runtime intents / startup manager /
   three bus drivers / estimation / trace), the four-layer deadline structure
   (1 kHz DRDY-gated fusion + state telemetry, 250 Hz wall-clock control,
   50 Hz retry-on-busy legs, 4 ms wheel slots + 6 ms servo poll, wall-clock
   diagnostics), peripheral bring-up order, and every ISR/main-loop
   concurrency contract.
2. **Detail pass** — boundary conditions (ring index `size`, NDTR reload
   sample, queue overflow, uint16 saturating counters, float→int casts,
   fusion-dt and elapsed-dt clamps), parser resynchronization, fault entry /
   transient recovery / re-issue, gate-open dispatch under every mode,
   calibration builds, tick wrap, and the HAL driver's actual interrupt and
   error semantics (read from `Drivers/STM32F4xx_HAL_Driver`, not assumed).
3. **Contract pass** — firmware `pi_link`/`pi_transport` vs the Pi-side
   `protocol.py`/`serial_node.py`/`runtime.py` (framing, CRC coverage,
   sequence gates, D0 dynamic gate mirror, action/telemetry scaling, health
   payload layout, joint wire order vs Actor order), and the generated
   constants in `kuafu_generated.h` against their `kuafu_physics.py` source
   of truth. The ST3215 sync-write register layout (ACC=41, position=42/43,
   speed=46/47) was confirmed against the repository's own design record.

## Findings and changes

### 1. (Medium) ST3215 write frames: both failure paths now recover through an explicit transmit abort

**Files:** `Core/Src/st3215.c` (`st3215_bus_step`), regression in
`tests/test_st3215.c`.

Write frames (sync-write, torque) elicit no reply; their only completion
event is the TX-complete interrupt. Two independent events can leave that
event missing: the interrupt is lost outright (recovered by the 20 ms
`ST_BUS_TX_ONLY` deadline with an explicit `AbortTransmit`), and a UART
error lands during the write (recovered through the deferred `error_pending`
path). The two coincide in practice — an error storm is exactly the
environment in which completion interrupts go missing — so both paths must
perform the same HAL-transmit-state reset before returning the bus to IDLE.
With the error path transitioning to IDLE without the abort, a coincident
lost completion wedges `gState` at `BUSY_TX` forever: every later
`HAL_UART_Transmit_IT` returns `HAL_BUSY`, all leg writes stop, the 100 ms
leg-hold window expires, the actuator supervisor closes the wheel gate on a
balancing robot, and `FAULT_SERVO` latches ~1 s later — with the deadline
backstop permanently disarmed (phase is already IDLE).

The error path now runs the identical abort + parser reset. A late
TX-complete after an already-finished transfer still finds the bus IDLE and
is ignored, and a truncated frame is dropped by the servo's own checksum,
so no new interleaving is introduced.

**Regression:** `test_st3215.c` queues a torque write, raises
`error_pending` inside the write budget, and asserts the applied step ends
IDLE with the transmit abort issued (`test_uart_abort_count`) and the bus
accepting new work immediately.

### 2. (Medium-low) Circular RX-ring re-arm preserves the lap truth

**Files:** `Core/Src/dma_rx_ring.c`, `Core/Inc/dma_rx_ring.h`
(`dma_rx_ring_rebase`), `Core/Src/main.c` (ordering + re-arm), regression in
`tests/test_dma_rx_ring.c`.

The absolute producer cursor of a circular RX DMA stream is reconstructed
as `lap_count * size + write_index`, where the lap truth comes from the
transfer-complete interrupt. A re-arm (post-error `AbortReceive` +
`Receive_DMA`) must anchor the consumer at the current lap boundary while
preserving every counted lap: the synchronous abort completes the old
stream, so a lap racing the re-arm is real production, not an artifact. The
Pi-side re-arm (`pi_transport_reset`) implements exactly this; the USART3
re-arm now does too, via the new `dma_rx_ring_rebase()` (which also keeps
the cumulative `overrun_count` diagnostic). Boot order matches the
contract: the ring is initialised before the peripheral that starts its
DMA. Erasing or inventing a lap skews the cursor by up to one ring (64
bytes) and re-feeds overwritten bytes to the parser as spurious checksum
failures.

**Regression:** `test_dma_rx_ring.c` covers old-stream lap preservation,
cursor anchoring, restarted-stream production from the base with no
fabricated loss, and absorption of a lap that raced the re-arm.

### 3. (Medium-low) Diagnostic telemetry runs on the wall clock

**Files:** `Core/Src/main.c`.

Diagnostic (0x83), health (0x84), and FAULT (0x8F) frames report fault
masks, per-device ages, error counters, mode, and reset cause — none of
which depend on the fusion path — and are paced by the SysTick millisecond
(250 Hz diag, 10 Hz health), not by the DRDY tick and not by
`g_imu.initialized`. When the IMU path dies (I2C failure or a stopped
data-ready line), the 250 Hz control section still latches the fault on the
wall clock and these frames still tell the Pi exactly what failed and how
long ago; FAULT broadcasts are no longer contingent on the health of the
subsystem being diagnosed. Fusion-state telemetry (IMU/joint frames)
deliberately stays on the DRDY tick and fusion gate: with the fusion path
down its values are frozen and worthless, and the health frame's age fields
already carry that information. The cadence divider is a `main()` stack
local, so the RW/ZI symbol table — and with it the SWD debug contract — is
unchanged.

### 4. (Low) Balance-trace boot marker wired

**File:** `Core/Src/balance_trace.c`, assertion in
`tests/test_balance_trace.c`.

`balance_trace_init()` seeds the pending event as
`BALANCE_TRACE_EVENT_INIT`, so the first recorded sample carries the boot
marker; a dump shows the boot boundary without correlating timestamps
against the reset cause. (The event type existed; nothing produced it.)

### 5. (Low) Telemetry quantization rejects non-finite inputs

**File:** `Core/Src/pi_link.c` (`quantize_i16`), regression in
`tests/test_pi_link.c`.

A NaN/Inf telemetry value returns the protocol's zero sentinel instead of
reaching the float-to-int cast (undefined behaviour in C). Zero is already
the documented unavailable/safe sentinel on these channels, so the encoding
of every finite value is unchanged. **Regression:** a NaN roll field
encodes 0x0000 while the adjacent finite pitch field is untouched.

### 6. (Low) `pi_link_on_tx_error` guards on `tx_active`

**File:** `Core/Src/pi_link.c`.

The error callback now carries the `tx_active` guard its completion twin
has: an error arriving while nothing of ours is transmitting (possible
after a failed `start_next_tx` left frames queued) is not about our
transmission and must not pop a merely queued telemetry frame. The callback
is near-unreachable in this configuration (no parity, no TX DMA; RX-side
ORE/NE/FE are filtered before it), which is the low grade; a stalled queue
self-heals on the next `pi_link_transmit`.

## Verified clean (no action)

Re-derived independently by this pass and found correct; recorded so the
next review can start from these as settled:

- **HAL interrupt/error semantics, from the driver source.** The DDSM
  single-byte IT reception survives ORE: `HAL_UART_IRQHandler` consumes the
  byte via `UART_Receive_IT` first (completing the 1-byte transfer, so
  `RxState` returns READY) and only then runs the blocking-error path, so
  the callback's `arm_rx` re-arm succeeds. The USART3 NE/FE swallow (SR/DR
  drain before HAL sees the flags, ORE still routed through the DMA-abort
  path) and the USART6 IDLE+DMA path match the driver exactly; the
  deaf-DMA watchdog closes the abort/re-arm race that the error callback
  alone cannot.
- **Concurrency contracts.** DDSM pending-queue cursors under the nestable
  PRIMASK sections; the masked re-validation of the DDSM timeout verdict;
  ST3215 deferred error application (ISR records, main loop mutates);
  `Pi_Command_Snapshot` / `Actuator_Feedback_Snapshot` context analysis;
  the balance-trace seqlock; `lap_count`-before-NDTR read ordering with its
  exact-or-bounded-undercount proof, including across the rebase.
- **State-machine composition.** The startup→INIT→STAND arming chain, the
  FAULT-gated enable sequencer feeding the supervisor's drop-and-return
  re-issue stage, transient-fault recovery, grace-window suppression
  (device-driven resets only), and the wheel-authorization revocation
  chain were each traced end-to-end, including the fault-entry-edge reset
  bookkeeping in `main.c`.
- **Zero-torque dispatch on gate-closed enabled wheels** (09-20-2 fix #1):
  re-verified against the current-loop-holds-setpoint rationale, including
  the safe-decoding property of a zero frame in a reverted velocity loop.
- **LQR/LQI and estimation.** Elapsed-dt clamp and 20 ms catch-up,
  integrator clamp and tip anti-windup, pitch-gated torque fade, leaky
  airborne re-anchor, one-shot hold re-anchor on link loss, yaw-rate
  damping under no-turn commands; the full sign chain (torque negation,
  `WHEEL_DIR_L/R`, yaw differential, residual signs) against the body-frame
  contract.
- **Mahony/BMI088.** Per-channel validity gating, gyro-only 100 ms bound,
  the init ladder with bus recovery bounded by the 15 s startup timeout;
  temperature-read failures cannot take the aggregate IMU health offline
  alone because the 1 kHz valid accel+gyro pair resets the consecutive
  failure streak.
- **Cross-layer contract.** `pi_link` ↔ `protocol.py` field-by-field
  (heartbeat/action/hello validation ranges, D0 gate mirror, health payload
  46-byte layout, telemetry scaling), joint wire order `[wheel_L, wheel_R,
  A_l, A_r, B_l, B_r]` ↔ Actor order `[A_l, B_l, A_r, B_r]` in
  `serial_node.py`, ONNX manifest gates, and the ST3215 register layout vs
  the design record (ACC 41, position 42/43, speed 46/47).
- **Resource/forecast arithmetic.** Telemetry TX budget vs 921600 baud,
  queue depths, IWDG window vs every blocking path, RAM image top
  (0x2001BFFF) below the SWD forensic dumps (0x2001FFC0/0x2001FFF0).

## Deliberate decisions left unchanged

Recorded so the next review does not re-litigate without new evidence:

- **DDSM feedback mode byte stays diagnostic-only.** A wheel motor that
  brownouts reverts to its default loop; the recovery path is the pitch
  fault. Runtime mode verification was reconsidered and again deferred: no
  field evidence of a single-motor brownout exists, and the feedback mode
  byte on this hardware reads 0x02 while the wheels demonstrably behave as
  a current loop, so it cannot serve as ground truth anyway.
- **LQR position estimate freezes while the wheel gate is closed.** On
  reopen, the elapsed-dt clamp integrates at most one 20 ms catch-up step;
  a 100 ms demotion biases `x_est` by ~4 cm, worth ~0.04 N·m through K0.
  Continuous integration was rejected: with the wheels torque-free the
  measured velocity reflects a falling robot, and feeding that into the
  position loop would re-open onto a larger, less predictable error.
