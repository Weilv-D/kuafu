# STM32 Firmware Logic Review — 2026-09-20 (fifth record)

This record documents an independent eighth-pass, whole-repository review of
the firmware and the Pi5 runtime. Per the task framing the review started
from the source alone: the module partition, the four deadline layers, every
state machine (mode, startup phase, actuator supervisor, bus transactions),
all driver concurrency contracts, the two circular-DMA RX consumers, and the
cross-layer protocol were re-derived before any prior record or changelog
entry was consulted. The seven earlier records were read only afterwards, to
cross-check conclusions; their invariants were re-verified and held, and one
of their encoded test expectations was found to pin a defect (finding 1).

It is a software record: no hardware was flashed or driven.

## Scope and method

1. **Architecture pass** — module partition (drivers / buses / health,
   safety machine, startup manager, actuator supervisor, runtime intents,
   control section, trace), the mode/phase/supervisor state machines and
   their interlocking gates, the four-layer deadline structure (1 kHz
   DRDY-gated fusion, 250 Hz wall-clock control, 50 Hz retry-on-busy legs,
   4 ms wheel slots + 6 ms servo poll), peripheral bring-up order, and
   every ISR/main-loop concurrency contract — including the two ring
   consumers' lap/NDTR reconstruction and their re-arm paths.
2. **Detail pass** — boundary conditions (ring index `size`, NDTR reload
   samples, queue overflow, saturating counters, float→int casts, fusion-dt
   and elapsed-dt clamps), parser resynchronization, fault entry/recovery/
   re-issue, gate dispatch under every mode, both bench calibration builds,
   tick wrap, and the IWDG budget against every blocking path.
3. **Contract pass** — `pi_link`/`pi_transport` against the Pi-side
   `protocol.py`/`serial_node.py`/`teleop_single.py`/`runtime.py`, the
   encoder non-finite guards, and the workspace-solvability of every IK
   input the scheduler can produce.

## Defects found and fixed

Three findings, all closed in this round with regressions. Severity is
ranked by worst-case consequence on the running robot.

### 1. (High) The Pi RX transport stalled permanently after a single ring overrun — the link went deaf until reboot

**Files:** `Core/Src/pi_transport.c` (`pi_transport_poll`), header contract
in `Core/Inc/pi_transport.h`, regressions in `tests/test_pi_transport.c`
(new `run_pi_transport_overrun_recovery_tests`), one corrected expectation
in `tests/test_pi_link.c`.

`pi_transport_poll` derived its parse span from
`ring_delta(read_index, write_index)`. The overrun branch adjusts the
consumer to exactly one ring behind the producer
(`consumed = producer - size`, `read_index = producer % size`) — and at that
point the two indices coincide while a **full ring** (256 B ≈ 2.2 ms of
traffic at 921600 baud) is still pending. `ring_delta` reports the
coincidence as zero, so the poll parsed nothing. The consumer then sat
exactly one ring behind the producer forever: every subsequent poll saw
`pending = size + (bytes since last poll) > size`, billed the freshly
arrived bytes as another overrun, reset `read_index` to the new write index,
and parsed nothing again. Heartbeats stopped being accepted,
`pi_link_heartbeat_fresh()` expired, `ACTIVE` demoted to `STAND`, and the
receive side of the Pi link stayed deaf until an STM32 power cycle —
outbound telemetry kept flowing, which made the failure look like a Pi-side
problem.

Reachability is ordinary, not exotic: any main-loop stall longer than one
ring period while the Pi streams. The firmware's own stall forensics exist
for >100 ms stalls; a 3 ms stall (a blocking BMI088 I2C transaction, a UART
abort, an interrupt burst) is unremarkable, and the boot sequence performs
multi-millisecond blocking I2C while the DMA is already running.

The same index-derived span also converted the documented laps/NDTR
sampling race (a lap completing between the two reads — the header's
ordering contract explicitly permits this as a bounded undercount) into
counter corruption: a stale sample under-advances the producer by one ring
while `write_index` is current, so `consumed_count` overshot
`producer_count`, the pending subtraction underflowed, and the overrun
branch billed an astronomically large "lost" count before corrupting both
cursors. The pre-existing test pinned the stalled behaviour as expected
(`consumed == producer - size` after the overrun), which is how the defect
survived seven passes.

**Fix:** the parse span is now derived from the absolute cursors
(`producer - consumed`, clamped to one ring), with `read_index ==
consumed % size` maintained as an invariant. The overrun branch drops
exactly the overwritten prefix, counts it, and then parses the still-valid
remainder of the ring in the same poll, so the consumer always catches back
up. A stale lap/NDTR sample can now only under-advance the producer for one
poll (absorbed by the monotonic max on the next), and `consumed_count` can
never overshoot `producer_count` — the race is harmless by construction
rather than by timing. The unused `ring_delta` helper was removed. The new
regression forces a full-ring lap with real heartbeat frames and proves
that fresh frames still parse after it (it fails on the pre-fix source with
`parsed == 0`, i.e. the deafness itself).

### 2. (Medium) The balance trace froze permanently after the first fault, blinding every later dump

**Files:** `Core/Src/balance_trace.c` (release logic, two new file-scope
statics), `Core/Inc/balance_trace.h` (contract comment), regression in
`tests/test_balance_trace.c`.

The first fault armed the 64-sample post-fault tail and set `g_bt_frozen`,
which `balance_trace_record` honoured as a permanent early return. The
three transient device faults (wheel/servo freshness) auto-recover by
design, so a single blip early in a session froze the 256-sample ring for
the rest of the session: a later crash's post-fault window was never
recorded (`record` returns before the pending FAULT event is consumed), and
every diagnostic after the first fault was lost — the trace is the primary
post-mortem artefact for exactly the crashes an operator investigates
after the fact.

**Fix:** the freeze is released when a **new** fault arrives after a
fault-free period (rising `fault_mask` edge — the newer evidence supersedes
the preserved window), or once the system has been fault-free for a full
post-fault tail (64 samples ≈ 256 ms), so the window is preserved across
the recovery transient and recording resumes afterwards. A latched serious
fault keeps the ring frozen by design: the robot is locked down and there
is nothing further to record. Health tracking runs ahead of the frozen
check so the release condition is evaluable while frozen. The two new
statics add 4 bytes of RW data, which shifted the SWD symbol addresses (see
verification); the release logic itself is invisible to the ring's ABI.

### 3. (Low) Non-finite LQR inputs would propagate NaN into the torque output

**Files:** `Core/Src/lqr_controller.c` (`lqr_update_elapsed_dt`), regression
in `tests/test_lqr.c`.

`clamp_float` passes NaN through both comparisons, so a non-finite
`elapsed_dt_s` (or any other non-finite input) flowed through the gains
into `out_tau_l/r`; the dispatch-layer clamps only bound magnitude and
would not stop it. Unreachable through the current call chain — every input
is validated upstream in the same control deadline — so the guard is for
future callers, the same latent-trap class as `ddsm_build_torque`,
`quantize_i16`, and `servo_angle_to_tick`; the safe sentinel is coast, never
a saturated command. NULL output pointers are rejected as well. Note for
future numeric tests: `TEST_NEAR` is NaN-blind (`fabs(0 - NaN) > tol` is
false), so the regression asserts `isfinite` explicitly.

## Bounded residuals and retained decisions

Derived end-to-end this pass and either proven correct or accepted with a
bounded worst case; recorded so the next review does not re-litigate
without new evidence.

- **A late TX-complete can race a newly started DDSM transaction** (retained
  from the 09-20-4 record, re-derived): worst case one lost frame plus one
  spurious health failure on the wrong target, self-healing on the next
  deadline.
- **ST3215 torque-enable frames are fire-and-forget**, so "servo enable
  verified" is software truth (retained, re-derived): mitigations are the
  FAULT-cycle re-issue and the pitch proxy plus 45° TILT backstop.
- **A mangled ST3215 echo can cost one protocol-failure count** (retained,
  re-derived): the echo filter exists because the adapter echoes TX onto
  RX; a partial echo flushed into the parser can fail one state-frame
  length check. Three consecutive failures are required to mark a servo
  offline, and any valid reply resets the streak.
- **A late DDSM reply can be misattributed to the current transaction**
  (retained, re-derived): a genuine reply from the previous query carries a
  valid CRC and the target ID, so it is accepted as current feedback — at
  most one transaction (~12 ms) of staleness on the freshness channel.
- **`Error_Handler` under a running IWDG is a reset loop** (retained): the
  intended self-recovery posture for bring-up fatalities; the reset cause
  is readable in the health telemetry.
- Re-derived clean, among others: the boot→INIT→STAND arming chain and the
  supervisor's observed-low latch under every entry path; the FAULT-gated
  enable sequencer; the grace-window suppression (device-driven only); the
  masked DDSM timeout re-validation; the ST3215 write-frame abort on both
  failure paths; the dma_rx_ring consumer (its span already comes from the
  produced/consumed cursors, so the ST3215 ring never had finding 1's
  stall — only the Pi transport did); the wheel-dispatch alternation and
  its sent-torque bookkeeping; the zero-torque gate-closed policy; LQR/LQI
  clamps, anti-windup, airborne leaky bucket, and the speed brake; Mahony
  per-channel validity and the gyro-only bound; the IK workspace proof for
  every reachable (qx, d0) input pair; the IWDG budget; and the cross-layer
  field order `[wheel_L, wheel_R, A_l, A_r, B_l, B_r]` ↔ Actor order
  `[A_l, B_l, A_r, B_r]`.
